# JNA Interface Mapping Detection

## What is JNA Interface Mapping?

Java Native Access (JNA) allows Java code to call native C functions **without writing JNI boilerplate**. The most common pattern is **Interface Mapping**:

```java
// 1. Declare an interface extending com.sun.jna.Library
public interface CLib extends Library {
    CLib INSTANCE = Native.load("c", CLib.class);
    int getpid();
    int sched_getaffinity(int pid, int cpusetsize, cpu_set_t mask);
}

// 2. Call native functions through the interface proxy
int pid = CLib.INSTANCE.getpid();
```

At runtime, JNA creates a dynamic proxy for the interface. When `getpid()` is called, JNA internally does:

```
dlopen("libc.so.6")  ->  handle
dlsym(handle, "getpid")  ->  function pointer
invoke function pointer
```

**Key insight**: The native symbol name equals the Java method name. This is the JNA convention that makes static detection possible.

## How JnaIfaceDetector Works

JnaIfaceDetector performs **static bytecode analysis** using SootUp's Jimple IR to resolve JNA interface calls without running the application. It determines:

- **Which native library** is loaded (`lib`)
- **Which native symbol** is called (`symbol` = method name)
- **Which caller** invokes it (`callerSig`)

### Architecture: 3-Pass Analysis

```
                        JARFILES_<image>/
                              |
                    +---------+---------+
                    |   SootUp Jimple   |
                    |  (bytecode -> IR) |
                    +---------+---------+
                              |
              +---------------+---------------+
              |               |               |
         [PASS 0]       [PASS 1]        [PASS 2]
        Accessor       Field Taint     Hit Detection
        Tracking       Population      (invokeinterface)
              |               |               |
              +-------+-------+               |
                      |                       |
               FIELD_TAINT map  ------------>-+
                                              |
                                     outputs_<image>/
                                      jna_iface_hits.txt
```

### Pass 0: Accessor Method Tracking

Java inner classes cannot directly access outer class private fields. The compiler generates synthetic methods like:

```java
// Generated by javac for inner class access:
static String access$000() {
    return LIBRARY_NAME;  // private field in outer class
}
```

Pass 0 scans all `access$NNN` methods and records the mapping:
```
ClassName.access$000 -> <OuterClass: String LIBRARY_NAME>
```

This allows Pass 1 to resolve library names that flow through accessor methods.

### Pass 1: Field Taint Population via `<clinit>`

Processes only static initializer methods (`<clinit>`) to find where `Native.load()` is called and which static field stores the result.

**Example bytecode (Jimple IR):**
```
// Original: CLib INSTANCE = Native.load("c", CLib.class);
$r0 = staticinvoke <com.sun.jna.Native: Object load(String,Class)>("c", class "LCLib;")
<CLib: CLib INSTANCE> = (CLib) $r0
```

**What Pass 1 does:**
1. Sees `Native.load("c", ...)` -> creates `LoadInfo{lib="c", api="Native.load(String,Class)"}`
2. Assigns to local `$r0` in `localTaint` map
3. Sees `putstatic` to field `<CLib: CLib INSTANCE>` from `$r0`
4. Stores in global map: `FIELD_TAINT["<CLib: CLib INSTANCE>"] = LoadInfo{lib="c"}`

**Handles these patterns:**

| Pattern | Example | Resolution |
|---------|---------|------------|
| `Native.load(String, Class)` | `Native.load("udev", Udev.class)` | lib = "udev" |
| `Native.load(Class)` | `Native.load(XAttr.class)` | lib = default C lib |
| `Native.load(null, Class)` | `Native.load(null, CLib.class)` | lib = default C lib |
| `Native.loadLibrary(String, Class)` | `Native.loadLibrary("c", CLib.class)` | lib = "c" |
| `Native.synchronizedLibrary(lib)` | wraps existing proxy | propagates inner taint |
| Conditional assignment | `Platform.isWindows() ? "msvcrt" : "c"` | lib = "c\|msvcrt" |

**Sorting and iterations:**
- Outer classes are processed before inner classes (inner classes depend on outer class fields)
- Pass 1 runs twice to handle transitive dependencies (inner class A -> outer class -> inner class B)

### Pass 2: Hit Detection via `invokeinterface`

Scans all methods looking for `invokeinterface` calls on Library-extending interfaces.

For each statement:
1. **Taint propagation** (same as Pass 1): tracks locals, field reads, string constants
2. **Hit detection**: For each invoke expression:
   - Check: does `callee.getDeclClassType()` extend `com.sun.jna.Library`? (BFS over interface hierarchy)
   - If yes: find `LoadInfo` from the receiver variable's taint
   - The **symbol** = `callee.getName()` (JNA convention: method name = native function name)
   - Emit hit with all metadata

**BFS hierarchy check** handles indirect inheritance:
```
StdCallLibrary extends Library
MyWin32Lib extends StdCallLibrary  -> still detected as JNA Library
```

### Post-Processing

After hit collection, two filters are applied:

1. **Platform exclusion**: Removes Windows/Mac/Solaris-specific hits (not relevant for Linux containers)
2. **Deduplication**: Same caller calling same symbol on same interface is reported only once (eliminates duplicates from retry loops or size-then-read patterns)

## Usage

### Running the Detector

```bash
# Compile
mvn compile -DskipTests

# Run on target JARs (output auto-derived to outputs_<image>/)
JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64 \
mvn exec:java \
  -Dexec.mainClass=com.echotrace.app.bytecode_new.JnaIfaceDetector \
  -Dexec.args="JARFILES_cassandra_5.0.6-bookworm"

# Or specify output directory explicitly
mvn exec:java \
  -Dexec.mainClass=com.echotrace.app.bytecode_new.JnaIfaceDetector \
  -Dexec.args="JARFILES_cassandra_5.0.6-bookworm outputs_cassandra_5.0.6-bookworm"
```

### Output Format

**`jna_iface_hits.txt`:**
```
callerSig | lib | symbol | apiPattern | interface | calleeSig | callerJar | calleeJar
```

| Field | Description | Example |
|-------|-------------|---------|
| `callerSig` | Method that calls the native function | `<LinuxHelper: int getpid()>` |
| `lib` | Native library name | `c`, `udev`, `rt` |
| `symbol` | Native function name (= Java method name) | `getpid`, `udev_unref` |
| `apiPattern` | How `Native.load` was called | `Native.load(String,Class)` |
| `interface` | JNA Library interface | `LinuxHelper$CLibrary` |
| `calleeSig` | Full interface method signature | `<CLibrary: int getpid()>` |
| `callerJar` | JAR containing the caller | `affinity-3.23.3.jar` |
| `calleeJar` | JAR containing the interface | `affinity-3.23.3.jar` |

**`skipped_methods.txt`:**
Methods that failed analysis (VerifyError, malformed bytecode, etc.)

## How This Fits in the EchoTrace Pipeline

JNA interface detection is one component of the bytecode-to-syscall mapping:

```
                    Java Bytecode Analysis
                           |
          +----------------+----------------+
          |                |                |
    JNA Interface    JNA Dynamic      JNI Native
    (JnaIfaceDetector)  (JnaDynDetector)  (NativeFileFinder)
          |                |                |
          v                v                v
    lib + symbol      lib + symbol     native method sig
          |                |                |
          +--------+-------+--------+-------+
                   |                 |
            Native Library      JNI Convention
            Symbol Lookup       (Java_pkg_Class_method)
                   |                 |
                   v                 v
              C Function in .so / .dylib
                         |
                    SysPart Binary Analysis
                    (callgraph -> syscalls)
                         |
                         v
                  Seccomp Profile (syscall whitelist)
```

The JNA interface hits tell us:
- **Which `.so` to analyze**: The `lib` field maps to a shared library
- **Which function to start from**: The `symbol` field is the entry point in that library
- SysPart then traces from that symbol through the library's call graph to find reachable syscalls

## Platform Filtering

Container security profiles target Linux. The detector excludes:

**Packages:**
- `com.sun.jna.platform.win32.*`
- `com.sun.jna.platform.WindowUtils`
- `com.sun.jna.platform.mac.*`
- `com.sun.jna.platform.unix.solaris.*`

**Libraries:**
- Windows: kernel32, user32, advapi32, ole32, shell32, ntdll, msvcrt
- Mac: CoreFoundation, IOKit, SystemB, libpthread.dylib
- Other: kstat2, X11

**Classes:**
- WindowsJNAAffinity, OSXJNAAffinity, SolarisJNAAffinity, X11KeyboardUtils

## Edge Cases and Limitations

### Resolved correctly:
- Inner class accessing outer class `INSTANCE` field via `access$NNN`
- `Native.synchronizedLibrary()` wrapper (taint propagates through)
- Conditional library names (`Platform.isWindows() ? "msvcrt" : "c"` -> reports both)
- Multiple interfaces in one JAR

### Not resolved (reported as `lib=<?>`):
- Library name computed at runtime (e.g., from system property or file)
- Library loaded via reflection
- Indirect proxy patterns where the interface reference is passed through multiple method calls (interprocedural)

### Deduplication:
- Same caller + same symbol + same interface = one hit (even if called multiple times in loops or retry logic)
- Different callers calling the same symbol = separate hits (both are valid call sites)

## Verifying Hits

Use `show_bytecode.sh` to decompile and inspect the source:

```bash
./show_bytecode.sh JARFILES_cassandra_5.0.6-bookworm \
  '<com.sun.jna.platform.linux.Udev$UdevContext: void unref()>'
```

This shows the decompiled Java source from the JAR to confirm the native call exists.
